# concepts — 学びと型

「次に同じ状況が来たとき、読み返す価値があること」を1つ1ファイルで置きます。

- 失敗から得た教訓（何をしたら何が起きたか）
- 繰り返し使える手順・型
- 判断基準（どういうときにどちらを選ぶか）
- 技術的な落とし穴と、その回避策

## 書式

```markdown
---
type: concept
updated: 2026-08-10
---

# 一行で言える結論

結論を最初に書く。「〜する」「〜してはいけない」の形で。

## なぜそう言えるか

何が起きて、そこから何が分かったか。具体例を1つは入れる。

## どう使うか

次に同じ場面が来たとき、何をすればいいか。

## 出典

- [[daily/2026-08-10]]
```

## 判断に迷ったら

concepts は entities と違って慎重に作ります。数が増えるほど価値が下がる層だからです。

- **原因と対策がはっきりしたときだけ書く。** 「うまくいかなかった」だけでは学びにならない
- 同じことが再発したときは、新しいページを作らず既存ページに追記する
- 一般論だけのページは作らない。自分の記録に裏付けがあるものだけ
- 見出しに結論を入れる。「ビルドエラーについて」ではなく「型エラーは import 順で出ることがある」
