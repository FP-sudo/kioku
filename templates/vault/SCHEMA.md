# この vault のルール

> このファイルは、kioku の編纂係（LLM）が読むためのルール定義です。
> 何がどこにあるかは [[INDEX]] を見てください。全部を読みに行かないこと。

## フォルダの役割と権限

| 場所 | 中身 | 誰が書くか |
|------|------|-----------|
| `daily/` | 日付ごとの記録。エージェントとのやり取りが自動で溜まる | kioku が追記。**編纂は読むだけ** |
| `entities/` | 人・会社・クライアント・ツール・サービス・案件 | 編纂が更新。人も自由に書ける |
| `concepts/` | 学び・判断基準・繰り返し使える型 | 編纂が更新。人も自由に書ける |
| `decisions/` | 月ごとの意思決定ログ（金額・契約・方針） | 編纂が追記 |
| `open-loops.md` | 未解決の宿題 | 編纂が出し入れ |
| `INDEX.md` | 全体の地図 | 編纂が更新 |
| 上記以外 | あなた自身のノート | **kioku は一切触らない** |

`daily/` を書き換えると、kioku が自動で元に戻します。記録が変わってしまうと、
編纂結果の裏付けが取れなくなるためです。

## 編纂の3原則

1. **差分最小** — 既存ページの全面書き直しをしない。変わったところだけ触る
2. **追記のみ** — 既存の記述を消さない。誤りが判明したら、訂正と分かる形で足す
3. **出典必須** — すべての追記に `[[daily/YYYY-MM-DD]]` を付ける

この3つを外すと、編纂は「毎晩ノートを書き直す機械」になります。
数週間で、自分の記録のどこまでが事実か分からなくなります。

## 書き方

- 本文は日本語。フォルダ名とファイル名だけ英語 kebab-case
- 1ページ1件。冒頭に1行の要約を置く（そのまま INDEX に転記できる粒度で）
- 日付は `YYYY-MM-DD`
- 内部リンクは `[[フォルダ/ファイル名]]`
- 事実と解釈を混ぜない。解釈を書くときは、そう読んだ理由も添える

## 書かない判断

その日の記録が定型作業だけなら、知識層には何も書きません。
無理にページを作ると、中身のないファイルが積み上がり、この vault は使えなくなります。
「更新なし」で終えるのは、正しい仕事です。
